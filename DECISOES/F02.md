Aplicação de Índice Invertido e a Interseção de Conjuntos, não usamos array para evitar duplicações de dados e usando Set como estrutura de dados podemos fazer buscas por valor mais rápidas, normalização dos textos com NFD e remoção de acentos e caracteres especiais no momento de filtragem, na interseção de conjuntos abordamos sempre do menor para o maior para diminuir custo de processamento.

Aplicação de Trie e Top-K por Heap (explicado no item 3), um .filter() aqui pode gerar muitas varreduras desnecessárias, usando o isEndOfWord como flag para encontrar o fim de uma palavra auxiliando a proposta do trie (Map), evitando o acumulo de pesquisas desnecessárias. Que por fim retornará sempre uma lista ordenada por importância declarada no item abaixo.
3. Top-K por Heap, funcionará como um sistema vip de 10 itens que serão avaliados por uma condição de drop zone, o restante da lista é comparada com o item do topo dessa lista funcionando como um drop zone, evitanto todo o custo de ordenar a listagem inteira.
4. Contagem de facetas, vamos percorrer uma vez a lista e identificar vendedor, condição, faixa de preço e país em uma passada só, evitando repassar várias vezes a mesma lista para cada momento, usando um Map em vez de object pois object contem propriedades que não precisamos consumir, o Map entrega os dados limpos para serem trabalhados e ainda insere uma camada de comandos que auxiliam na distribuição das facetas que buscamos. Fazemos esse contador através de um unico reduce em cima do Map contato cada faceta proposta.
5. Aplicação de Ordenação Estável Multi-chave, uso de desempate determinístico na ordenação (id), tendo ordenações mais importante como principais, como atributo preço, mas podendo haver valores idênticos no preço será necessário usar um desempate prático. Isso impede de acontecer flicker no layout do front, onde um item pode mudar de lugar em caso de empate na ordenação. Sem desempate determinístico, a paginação repete ou pula item.
6. Aplicação de Cache LRU com Map, uso de um Map para manter até 5 itens de acesso rápido, o uso do Map é estratégico pelo fato de um Object não guardar a ordem de inserção em casos de chaves parecerem inteiros ("111") e também não há uma busca direta para o item mais antigo. O Map faz isso e isso serve como uma fila (mais recente para o mais antigo) mas podendo ser alterada de acordo com um "reacesso" de algum desses 5 itens, reordenando a lista. Conforme os acessos ocorrem o mais antigo deve sair da listagem.
7. Aplicação de Paginação por Cursor. A paginação por cursor, é para evitar problemas de perda de referência que um offset pode oferecer no nosso caso em específico, o cursor vai recupera a lista através de um "after_id:" e uma quantidade "limit" e teremos uma trava (temMais/hasMore) verificando se existem mais itens após o id usado na busca isso evita problemas de busca e também um nextCursor já evidenciando o próximo id ou não (null) a ser usado em uma nova busca.
